# 登录页布局与滑块验证

按用户指定参考 `https://ele.vben.pro/#/auth/login`，复用固定 v5.7.0 的 AuthPageLayout、原有插画和登录表单，使用 DevPlatform／BaJie Dev 品牌。保留三种登录布局、主题、偏好入口、记住账号、真实认证和强制改密。在线浏览器连接不可用，以官方固定来源的布局代码为可核查依据，不宣称逐像素复刻在线最新版本。

滑块选择参考页的拖动至末端模式，复用 VbenSliderCaptcha；增加键盘操作、状态提示、失败重试及过期重置。相比单纯前端 boolean，增加服务端一次性流程；相比引入第三方 CAPTCHA，本阶段无新依赖、外部服务或凭据配置。它是交互门槛而非强人机识别，自动化仍可模拟；需要对抗机器人时应另接专业服务。

服务端契约：POST /auth/captcha/challenge 创建 120 秒挑战，HttpOnly/SameSite=Strict/生产 Secure Cookie 绑定浏览器；POST /auth/captcha/verify 校验完整进度与最短服务端等待，消费挑战并返回 60 秒一次性 captchaToken。POST /auth/login 必须先同步消费有效 Token，再验证账号密码；错误密码同样消耗，重放、并发重用、跨浏览器、过期均拒绝。均校验 Origin、限流、no-store；内存容量有上限、按到期清理，符合当前单进程实例约束，重启后需重新验证，无数据库迁移。

影响：登录 API 新增必填 captchaToken，更新 DTO 生成契约、全部调用者和测试。服务端集成使用真实挑战流程（不增加测试绕过）；新增缺失／伪造／过期／跨浏览器／重放／并发／限流否定用例，浏览器拖动及键盘验证、错误密码后重置、刷新失效、深浅主题和窄窗口截图。先生成契约及静态构建，再执行专用测试库上的集成和 E2E，避免构建与 Vite 浏览器测试互相热重载。
