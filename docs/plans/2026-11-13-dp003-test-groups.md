# DP-003 测试分组实施方案

版本：1.0；级别：T2；状态：A-010已批准，已实现／本地验证完成，待提交归档。用户在具体方案确认请求后回复“继续”，仅批准DP-003本方案。

## 目标与审查结论

将现有真实 MySQL 集成测试按风险分组，支持定向运行，默认仍执行完整套件。当前 tests/integration.ts 的用例共享账号、台账 ID、角色及会话状态；不能只在 check 函数加过滤，否则会跳过后续用例的必要状态变更。CI 目前 api:check、build 和 test:integration 均可能触发 Server 构建，可复用同一工作流已构建产物。

本任务不改变业务 API、权限、会话或数据库结构，不升级依赖，不减少现有断言、故障注入及真库验证。DP-004 及部门／数据范围分别后续审查。本地 Docker 当前未运行，实际真库耗时和可用环境须在实施时核对，不沿用历史结果冒充新验证。

## 文件与步骤

1. tests/integration.ts 保留为统一入口；新增 tests/helpers/ 和 tests/integration/，提取环境保护、应用／数据库生命周期、请求及账号夹具。每组独立建立前置数据，清理只针对本次随机标识；初始化失败也尽可能关闭已建立资源。
2. 分为 transport（健康、响应、请求体与 HTTP 方法约束）、records（台账输入、逐操作范围、幂等、版本、事务与数据往返）、identity（滑块、身份、改密、刷新／撤销及系统用户角色菜单授权）。identity 保留关联流程及最终限流用例顺序；组内不并行。建立原有全部 check 名称到组的映射，对照实际原始数量，不仅依据历史“30组”。
3. 支持 --group transport|records|identity，允许重复参数选多组；无参数跑全部。未知组、未知参数、缺值及空选择在连接数据库前非零退出。输出选择、各组数量、总数量与耗时，零用例不能报成功。
4. package.json 保留 test:integration 的构建后默认全套行为；拟新增 test:integration:run 直接运行已构建产物，供同一 CI 工作流构建后使用，并明确它不检查源码产物新鲜度。定向示例：pnpm test:integration --group identity；复用示例：pnpm test:integration:run --group identity。
5. Playwright 保留现有 authorization.spec.ts、framework.spec.ts、shell.spec.ts 文件分组及单 worker。文档给出按文件执行的现有命令；不引入可能零匹配成功的自定义 E2E 筛选。CI 仍执行全套集成与 E2E，只将重复构建的集成步骤改为复用入口；远程结果须实际运行后才能记为通过。
6. 更新 README 测试说明及 TODO，记录批准范围、用例映射、实际结果和耗时。

## 验证与停止条件

- 改前记录全套 check 清单；改后核对名称、断言与故障恢复没有遗漏。分组独立运行后，默认全套至少跑一次，对照集合一致。
- 验证全部合法分组及多组选项；非法／空筛选在环境检查和 DB 初始化前失败。校验专用环境保护仍生效。
- pnpm build:server；pnpm exec tsc -p tsconfig.server.json --noEmit；对修改的 TS 文件运行现有 oxfmt／oxlint；pnpm check:boundaries；git diff --check。
- 真库串行执行三个单组及默认全套，分别记录耗时，定向失败只复测相关组；不同时使用共享可变测试库。使用既有 dev-platform-test 专用环境，核对环境后才执行迁移／夹具。
- pnpm test:e2e 全套一次，检查共享夹具提取没有破坏浏览器链路；不重复 Web 构建或全仓单元测试。若不修改 E2E 配置和夹具且集成夹具无外部影响，经实际差异审查可复用已有 E2E 证据并明确未重跑。
- 主要成本为真实滑块等待、密码哈希、三个独立组与一次全套；当前无可靠新耗时估计。环境不可用则记录阻塞，不填写通过。

## 风险与恢复

主要风险是隐藏夹具依赖、全局限流污染与清理遗漏，采用每组独立应用实例、组内原有顺序和随机夹具处理。保留原入口与默认全套；失败仅撤销本任务测试／脚本调整，保留工作区既有改动。不操作生产、远程发布或删除数据卷。
