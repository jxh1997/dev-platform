# DP-004 认证与会话验收补齐方案

版本：1.0；级别：T3；状态：待用户确认。前置DP-001、DP-003已完成。

## 审查结论与范围

已有真实认证、滑块、角色与逐操作ALL／SELF、会话撤销、刷新复用撤销和最后管理员竞争，不重写。新identity分组保留20组现有验证，但不能据此代替AC01—06、09—10、40—41完整验收。

实际缺口：CLI只有run／show／seed／admin，已有管理员初始化后拒绝再次执行，尚无紧急恢复命令；前端refreshTokenApi已有单标签Promise合并及Web Locks，尚缺真实多标签／不支持锁／刷新响应丢失的验收。后端严格轮换并在旧凭证复用时撤销会话；产品明确允许丢响应后重新登录，不引入宽限重放。

## 实施步骤与位置

1. tests/integration/identity.ts及新认证专项测试：补未知账号／错误密码响应一致、登录限流、并发刷新与旧凭证撤销、撤权提交后新请求拒绝、DB故障／审计失败时无成功会话或权限写入。保留现有20组；新增用例同步分组数量及映射，旧断言不得减弱。
2. 新tests/认证初始化CLI专项入口：使用明确命名的专用新MySQL Compose项目和卷，MySQL不暴露远程端口；验证空库迁移、两个admin初始化进程竞争只能成功一次、再次初始化不改原密码／权限、重启不重复创建。不得重置现有dev_platform_test的bootstrap状态或清空共享测试库；保留专用卷供核查，不删除未知卷。
3. packages/database/src/cli.ts及按需抽出的CLI内部用例：新增受控admin-recover命令及根package.json对应入口。仅恢复已有、关联启用super-admin受保护角色的指定账号；要求显式目标ID、当前version、非空恢复原因和通过环境变量隐藏输入的新密码。拒绝创建账号、为普通账号授予管理员或自动启用被停用的角色。恢复原因20—500字符并禁止写入凭据；密码规则沿用6—12字符及bcrypt12。
4. 恢复事务先锁sys_security_state固定行，再重读目标、角色关系及version；按ID＋version更新密码、enabled=true、mustChangePassword=true，递增version和securityVersion，撤销该用户全部会话并递增authzEpoch。原因及无密码／哈希的差异以系统主体0、明确目标ID记录system:admin:recover审计，审计失败全部回滚；同version并发恢复只成功一次。拒绝未完成初始化或待迁移结构；无HTTP入口、无新表／迁移。不记录密码、令牌或哈希。
5. tests/e2e/新增会话规格及现有登录滑块规格：同一浏览器上下文两个真实页面验证续期、同页并发合并、刷新响应丢失、无Web Locks回退；确认有限请求后继续有效或重新登录、写请求不自动重放。真实请求保持后端处理，只在浏览器传输层制造到期响应／丢响应，明确区分这些夹具与真实JWT过期的后端验证。离开登录页再返回须重新滑块。必要局部修复限于apps/admin-web/src/api/core/auth.ts、api/request.ts及已有登录凭证生命周期，不新增令牌持久化或改变轮换契约。
6. 更新认证模块、README恢复操作说明、TODO与逐项验收证据。逐项标明本任务的实际覆盖及待验边界，不提前签署M1。

## 验证命令与成本

- 先执行拟新增的CLI／认证定向入口与 pnpm test:integration --group identity；使用真实MySQL与合成账号，故障注入后恢复连接／原方法，不能凭Mock通过判定事务正确。
- 新CLI专项命令在实现后加入package.json，实际命令及隔离项目参数随交接记录；本计划不声称已有该脚本。
- pnpm build:server、pnpm exec tsc -p tsconfig.server.json --noEmit、修改TS的oxfmt／oxlint、pnpm check:boundaries。仅契约变化才需api:check；本方案不计划新增HTTP契约。
- 如需前端实现修改，先按AI.md读取vue-best-practices对应条目，执行Web类型检查和pnpm build:web，再跑浏览器；只有测试变更时复用未变的Web构建证据。
- pnpm test:integration:run完整回归；pnpm test:e2e新增会话及既有认证／滑块规格，认证共享行为发生变化则执行完整E2E。共享可变测试库串行，独立CLI库也不与浏览器争用端口。
- 慢项为专用库首次迁移、bcrypt、Web构建及真实浏览器故障场景；没有可靠总体耗时估计。定向失败修复后仅复测受影响场景，必要检查通过停止，不附带全仓依赖扫描。

## 风险、回退与授权边界

CLI恢复具备高权限，只由拥有实例数据库／运行环境操作权的维护者显式执行；默认流程继续后台管理，普通应用用户无法调用。新增命令必须给出清晰目标与结果、拒绝缺项及版本竞争，敏感诊断不输出。验收只在明确隔离的本地实例运行，不对真实管理员执行恢复。

恢复失败同事务回滚；提交后的密码变更不自动回退为旧密码，若需再次恢复必须新version、原因和审计。代码失败只撤销本任务变更，保留既有工作区。部门、五种数据范围、数据库结构、生产／远程发布及glibc修复不在本方案中。
