# 安全、文件与异步任务规范

版本：V1.0 · 规则前缀：SEC、JOB。

## 1. 身份与安全

SEC-01：生产 HTTPS；JWT 明确算法、iss、aud、有效期、sid；用户禁用、重置密码、撤销会话后新请求拒绝。Refresh 存 HttpOnly＋Secure Cookie，服务器存哈希，默认 7 天绝对有效期；轮换不无限延长。

Refresh 在会话事务锁下原子替换。旧凭证重用按严格策略撤销会话；合法跨标签竞争由前端协调，无法安全续期时重新登录。Cookie 修改接口实施 Origin／CSRF 防护，清除 Cookie 使用匹配的配置。

不发明密码可逆加密；密码经 HTTPS 到达后端，由成熟哈希库处理。参数、文件、前端构建和日志都不存秘密。密钥按实例独立配置，不提供公开默认管理员密码。

## 2. 授权代次

SEC-02：影响角色权限、用户角色／部门／状态、部门树、记录归属和模块授权的变更，在同事务递增 sys_security_state.authz_epoch。全局代次可能使无关用户的旧导出失效，这是首版接受的简化。

导出开始、完成提交、下载都检查代次与当前权限。完成提交和授权变更采用统一的安全状态锁顺序。已下载内容无法收回，禁止宣传“撤权后客户端文件自动失效”。

## 3. 文件生命周期

SEC-03：文件元数据、随机 storageKey 和业务 fileId 分离；不返回物理路径，不将整个上传目录挂公开静态路由。校验扩展名、实际内容、大小和路径，HTML／SVG 等可执行内容默认不内联。

临时文件仅上传者访问；业务附件通过至少一条当前可读且允许下载的有效关联授权；复合机密文件由模块采用更严格策略；导出文件通过任务归属、操作权限、代次与有效期授权。通用 file:read 不能取代业务授权。

数据库事务负责元数据和引用，存储写入用临时态、不可变最终键和对账补偿。存在引用禁止物理删；清理失败保留记录并有限重试。清理任务自己也要防止和新引用并发竞争。

## 4. 导入

JOB-01：受控 xlsx，仅新增，默认最多 1,000 行／10 MiB，另设解压体积、工作表／单元格数量、文本长度与解析超时。解析隔离，拒绝宏、公式及外部引用，条码和长数字按文本处理。

预检绑定原文件哈希、模板版本、规范化结果及用户；确认重新验证状态、权限、唯一性、归属和引用。整批事务，有任一错误不提交；幂等键和批次状态锁防重复。

Committing 属提交事务内状态，进程退出由事务回滚；若确认失败需持久化失败原因，应在回滚后条件记录独立失败结果，不误把已提交批次改为失败。错误行预览默认 100 条，完整报告独立鉴权。

## 5. 任务真源与处理顺序

JOB-02：MySQL sys_task 为业务真源，sys_task_dispatch 为投递记录，队列只传 taskId、投递代次和必要版本标识；不塞入完整导出数据、角色或长期有效的授权范围。

受理事务写 task、dispatch、幂等结果后返回 202。投递器通过稳定标识投递，如 `task-123-g2`，同一代次重试保持 ID；jobId 不用冒号，不直接使用纯数字。队列清除后同 jobId 可再次进入，因此去重不能只依赖队列。[参考资料 1]

Worker 支持消费先于投递状态回写：从 Pending／Queued 条件认领，不被投递器回写为旧状态。认领生成 leaseToken、attemptNo、租约和心跳；重复消费只有一个有效执行权。

JOB-03：数据库策略是自动业务重试的唯一权威，BullMQ 不另加一层同类重试。重试区分依赖临时故障、权限失败、超限和永久错误；默认可恢复失败最多 3 次。任务彻底丢失时数据库对账产生新投递代次，而非盲目假定旧 job 可重新执行。

## 6. 导出发布与下载

1. Worker 重新识别发起用户、功能权限和逐操作范围；记录 authzEpoch。
2. 稳定排序／游标分批读取，限制行数、并发、耗时和内存；普通清单不承诺完整业务快照。
3. 输出到含 taskId、attemptNo 和随机值的临时文件；最终键唯一不可变。
4. 生成成功不等于任务成功。完成事务校验有效租约、执行代次与当前 epoch 后才写文件引用及 Succeeded。
5. 旧 Worker 失去租约后不可提交结果，也不可清理新执行的产物。
6. 下载重新检查归属、功能、代次、有效期和文件存在性。空结果给表头，超限明确失败，不截断伪成功。
7. 用户文本写为文本单元格，禁止可控内容成为公式；金额／ID 按契约格式，文件不含未授权列。

手动重试创建新任务并引用 originalTaskId；系统自动尝试保留原任务并增加 attemptNo。两者在 UI 和状态里区分。

## 7. 运行、清理与故障

JOB-04：Valkey 持久化、noeviction、受控网络，不与任意淘汰缓存共用实例。Worker 与 API 共用同实例文件空间；不共享不同客户路径或队列凭证。

队列不可用保留待投递记录；达到容量上限返回 503。数据库不可用不受理新任务；输出已生成但提交失败时保留可恢复临时产物并对账。租约过期、孤儿文件、缺失任务和失败清理均有扫描与告警。

任务结果过期立即禁止下载，与物理清理是否成功无关。清理不删除仍被当前成功任务引用的文件。

导出可受控重算，不代表支付、通知、设备控制可以重复执行。这些业务必须另定义外部幂等、确认与补偿协议。
