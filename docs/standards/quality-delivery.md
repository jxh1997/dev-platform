# 质量、测试与交付规范

版本：V1.0 · 规则前缀：QA、REL。

## 1. 按风险选择验证

QA-01：验证服务于真实风险，不能用统一“写完测试即可”替代执行。无风险的文字与样式修改不机械新增单元测试；权限、迁移和事务必须有相应否定／并发／恢复证据。

| 改动 | 最低检查 | 加强场景 |
|---|---|---|
| 文案／样式 | 页面检查；受影响类型／构建 | 断行、禁用、长文本、键盘焦点 |
| 表单／普通 API | DTO、业务回归、契约与类型 | 空／null／越界、重复提交、409 |
| 新模块／范围 | 受影响单元、真库集成、真实 API 与页面冒烟 | 直接越权、批量混入、统计／导出与附件 |
| 数据库迁移 | 空库及上一发布结构升级 | 既有数据、唯一约束、部分 DDL 失败与恢复 |
| 会话／管理员 | 并发及撤销测试 | 刷新重用、多标签、最后管理员竞争 |
| 导入／导出／队列 | 真库＋真实队列的集成与故障注入 | 重复投递、租约、撤权、磁盘／依赖故障 |

权限至少测试超级管理员、部门管理员、普通用户和未登录。既要功能权限不足，也要功能允许但数据不可见。列表总数、详情、修改、删除、远程选项、统计、批量、导入、导出和文件逐项验证，未提供的能力标明不适用。

### 最小充分验证与停止条件

- **仅协作规则／文档／技能提示词**：检查差异、链接、规则一致性及技能格式，不启动应用、数据库或整套业务测试；不新增只验证文字措辞的测试。
- **局部修复**：优先复现该缺陷，修复后只跑直接相关用例与受影响的静态检查。无行为变化不机械新增测试；普通页面变化验证目标页面和受影响状态。
- **高风险／公共能力**：按上表保留必要真库、越权、并发及关键 E2E，不默认扩大到所有模块。现有脚本无法定向且确实需要时才运行其整组，并在计划说明；未实现的筛选命令不能当作已存在。
- **执行顺序**：先静态检查／契约生成／构建，再跑依赖这些产物的浏览器验证。不得并行构建共享包与 Vite E2E，不并行运行共用测试库的可变夹具；独立、不会互相污染的检查才并行。
- **避免隐式重复**：先看脚本的前置步骤；同一源版本已生成／构建的产物可复用，不为每条命令无故再构建。没有现成安全复用入口时先用现有脚本，不能静默跳过必需步骤或临时杜撰命令。
- **失败后**：先定位失败摘要，再只复测失败用例及受修复影响的关联用例。连续两次同类失败后禁止第三次原样重跑整套，先缩到最小复现、区分实现／夹具／环境问题；需要超出已批准范围或显著增加验证成本时提交差异计划。
- **结果有效期**：记录检查对应的相关代码状态。文档、截图或无关模块调整不使已通过检查失效；相关共享状态、认证生命周期或契约再次改变则重测受影响范围，不能沿用旧版本结果冒充新版本通过。
- **结束条件**：批准计划的必要检查通过且没有未解风险即交付。不为补一张截图重复整套 E2E；使用目标页面或对应用例。无法执行的检查说明原因与影响，不能悄悄省略或宣称通过。

大改动计划列出“检查／覆盖风险／执行命令／预计慢项／何时重跑”。只在已有记录支持时估计耗时，不承诺固定 Token 或时间节省比例。开发验证聚焦当前影响范围，CI／发布门槛按其配置保留，不因本节自动降低。

## 2. 测试环境保护

QA-02：测试使用专用 MySQL／Valkey／文件目录和独立凭据；执行破坏性 setup 前校验 APP_ENV、实例标识、数据库名和连接目标。仅凭 `_test` 后缀不足以确认安全。生产地址命中或环境不明时立即阻断。

测试数据用固定构造器，禁止直接复制客户原始数据。锁、DATETIME、BIGINT、索引与事务用实际 MySQL 验证，不用 SQLite 替代后宣称通过 MySQL 验证。Mock 用于纯逻辑与故障分支，不替代真实链路。

测试结束只清理本次专用空间，不执行无范围 `docker system prune` 或删除不明卷。并行测试使用隔离库／事务策略，清楚说明不能跨请求事务回滚的场景。

## 3. CI 目标门槛

QA-03：脚本接入后，按受影响范围执行：锁文件安装、lint、typecheck、启用应用构建、边界检查、契约漂移检查、受影响单元与集成。认证授权、DB 及核心公共包变更扩大回归范围；页面流程变化运行关键 E2E。

| 检查 | 阻断内容 |
|---|---|
| boundaries | 禁止依赖方向、循环依赖、前端引后端、跨模块私有导入 |
| api:check | DTO 变化但契约产物未更新，前端类型漂移 |
| permission coverage | 新业务路由既无权限声明也无显式公开声明 |
| migration integrity | 已发布迁移校验和变化、实体改变但没有对应迁移／说明 |
| secrets | 密钥、凭证、客户数据进入提交 |
| unit／integration／e2e | 对应风险行为不符合契约 |

这些是应实现的检查，不声称当前已有工具。接入时可先用简单脚本＋lint 规则；无法自动判断的规则由审查清单补足，不能把一条复杂策略的“关键词扫描通过”当作完整安全验证。

## 4. 合并前检查

- 改动对应明确用户故事，范围无意外扩张。
- 字段、权限、API、事务和模块文档一致；生成文件来自当前源定义。
- 受影响检查已运行，失败已解释；没有删除／弱化测试规避失败。
- 无秘密、日志原始数据、无意义格式化和无用依赖。
- Migration、种子、配置默认值与旧客户端兼容性已说明。
- 文件和任务涉及的异常、越权、重试与清理行为已验证。

## 5. 完成定义

QA-04：新模块只有在真实后端闭环、权限范围、字段映射、迁移、前端关键流程及失败反馈均在约定范围内完成验证，才能称“模块已完成”。部分接口或 Mock 页面仅标记对应部分已实现。

检查报告写出命令、版本、环境、结果和证据定位。未运行明确为未验证；缺依赖或权限明确为受阻。已实现、已验证、已发布分别记录，不相互替代。

## 6. 发布与恢复

REL-01：发布单元包括 Web、Server、Worker、迁移与配置。发布清单记录软件版本、底座／行业产品来源、commit、镜像 digest、依赖锁摘要、迁移顺序与校验和、配置差异、已知问题和恢复步骤。已发布 tag／镜像内容不可悄悄替换。

单机默认维护窗口停写：备份→控制入口及任务→确认在途事务→唯一迁移进程→更新应用→冒烟与核对→恢复访问。不能仅回退镜像就假定数据库也已回退。旧应用不兼容新结构时，执行已演练的前滚或恢复方案。

REL-02：数据库与文件备份使用一致 backupSetId；停写范围含上传、导入提交、业务写入与 Worker 发布。验证文件哈希、引用、记录数及抽样业务；备份存在不等于可恢复。必要密钥受控独立保存，备份不只放同一磁盘。

恢复 RPO／RTO 在实例条件下演练，不能把默认目标写成 SLA。客户迁移冲突、种子覆盖、来源提交重复回补都在升级分支解决，不在正式库即兴试错。

## 7. 最小验证报告

使用 [验证交接模板](../templates/verification-report.md)。低风险小任务可在 PR 或回复中报告，不强制生成永久文件；核心发布、迁移与恢复报告必须保留。
