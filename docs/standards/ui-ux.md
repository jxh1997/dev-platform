# 管理后台 UI／UX 与视觉质量规范

版本：V1.0 · 规则前缀：UI · 适用于 `apps/admin-web/` 的新页面、组件和界面改版。

目标是专业、克制、清楚、易操作的业务后台。审美通过信息组织、排版、对齐、留白和一致的交互体现；不通过默认圆角、蓝紫渐变和卡片堆叠制造“设计感”。已有页面不因本文件新增就自动视为完成改版。

## 1. 技能与项目边界

按 [AI.md 第 12 节](../../AI.md#12-ui-开发与技能工作流) 为实际任务选择技能，不默认全部加载；安装／来源审查时才读 [UI 技能基线](../architecture/ui-skill-baseline.md)。技能是工作方法，不替代产品基线和项目约束。

固定 Vue 3／TypeScript／Element Plus 及 v5.7.0 前端来源，优先使用既有组件、表单、表格、弹窗、路由、请求和主题能力。不得因技能示例切换 React／Next.js、引入另一套组件体系或升级固定底座；不在 `@vben/*` 散布业务样式和逻辑。业务 API 仍仅使用 GET／POST。

## 2. 信息与布局

UI-01：先确定使用者、本页主要任务、最高频操作和信息优先级，再选择布局。新页面／显著改版按 AI.md 分级，大改动先内部审查、提交布局与实施计划，用户确认后编码；计划内样式细节不反复审批。局部修复保持已有边界，不强制产出整套设计文档。

- 列表优先“紧凑页头／操作栏 → 筛选 → 连续表格／列表 → 分页”。不把普通 CRUD 页面套成营销落地页。
- 页头服务于定位和操作，避免巨幅标题、无业务含义的英文眉题、宣传口号及大块空白挤占工作区。
- 卡片用于独立对象、真实摘要或明确的任务分组；普通信息优先通过排版、分隔和背景层级组织。不默认添加三张 KPI 卡片，不将每个字段、按钮和表格再包一层卡片。
- 统计需有真实数据、范围和业务用途；不把“有序”“智能”“BASELINE”等装饰词放进指标位，不编造趋势、百分比或图表。
- 筛选、搜索和主要操作位置稳定；相关内容遵循同一对齐线和间距节奏。长表格只在明确的内容区域滚动，不让页头和操作区无意溢出。

## 3. 排版、颜色与形状

UI-02：使用现有主题变量和组件 token；新增语义 token 集中维护，不在各页面复制不同的颜色、阴影、圆角和字号。

| 项目 | 默认方向 | 禁止作为默认模板 |
|---|---|---|
| 色彩 | 中性色承担大部分面积，品牌色强调主要操作；状态色表达明确语义 | 蓝紫渐变铺底、彩色光晕、每个区块不同高饱和色 |
| 排版 | 正文清楚可读，标题、标签、辅助信息形成有限层级；中文后台优先稳定的本地字体栈 | 所有页头都用超大标题、装饰性英文字体、无需求加载外部字体 |
| 间距 | 复用项目间距尺度，区分组内与组间留白，按任务选择信息密度 | 每个小区块都用巨大 padding，或为了密集让标签和操作拥挤 |
| 圆角 | 由组件角色决定，普通控件和内容区优先小圆角／直角；胶囊只用于有语义的标签等场景 | 所有容器统一大圆角、无意义圆形／胶囊按钮 |
| 层次 | 优先留白、细分隔和轻背景；浮层与可拖拽层使用适度阴影 | 每张卡片都厚阴影、渐变描边、玻璃拟态和嵌套边框 |
| 图标 | 复用现有图标体系，必要时配文字，保持尺寸与线宽一致 | 用 emoji 替代功能图标、给所有标签加装饰图标 |

蓝色品牌主色、小圆角和必要卡片本身不被禁止；每项装饰必须能说明其分组、强调或反馈用途。不得用“避免 AI 味”作为更换另一套千篇一律风格的理由。正文对比度至少 4.5:1，大字至少 3:1；启用的深浅主题均使用正确语义色，不硬编码白底黑字破坏主题。

UI-03：一页保持连贯的设计语言。仪表盘、列表、详情、表单按任务组织，不共享同一份装饰模板；同类控件和同类操作保持一致。没有业务意义的模块直接移除，不用随机渐变或卡片补空位。

## 4. 交互与可访问性

UI-04：页面须完成交互状态，视觉效果不能遮蔽业务反馈。

- 每个操作区域优先一个明确的主操作；其他操作降低视觉权重。危险操作与普通操作区分，并说明对象和影响。
- 表单有可关联的标签、必填与格式提示；错误靠近字段，提交后可定位首个错误。placeholder 不代替标签，不阻止粘贴。
- 请求发出后显示提交中状态并防重复；失败保留输入，409 引导重读比较，不能自动用新 version 覆盖。未保存更改离开时按实际丢失风险提示。
- 加载、空、错误、无权限、禁用、成功和结果待确认状态按 [前端规范](frontend.md) 实现；空列表与请求失败不能使用同一提示。禁用原因和失败后的下一步应可理解。
- 图标按钮有可访问名称；操作使用 button，导航使用链接。键盘可达、Tab 顺序合理、焦点可见，不能只靠 hover 或颜色传递关键信息。
- 弹窗／抽屉复用现有焦点管理、关闭和返回焦点能力；保存中不得无意丢失输入，不重复自造组件库已提供的交互逻辑。
- 长中文、长编码、空值、长列表和缩窄窗口下仍可读可操作；表格数字列对齐，精度、时区和纯日期规则继续遵循接口与数据规范。
- 动效只用于状态与空间关系反馈，优先 transform／opacity，并尊重 reduced motion；禁止无依据的背景动效、数字跳动和 `transition: all`。

## 5. Vue 实现与代码质量

UI-05：遵循 Vue Best Practices 的职责划分与类型约束，结合本项目现有约定实施。

- 默认 Composition API、`<script setup lang="ts">`，区分页面编排、表单 UI、字段 schema、请求和有状态工作流；复杂单次使用的表单可以独立组件，无真实跨模块复用时不提为公共组件。
- 状态有明确所有者与生命周期，派生数据用纯 computed；副作用按需 watch，异步请求、监听、定时器和观察器按所属组件清理。
- props／emits／必要的 v-model 契约明确且有类型；避免巨型 SFC 和万能 `usePage()`，也不按固定行数机械拆出空组件或多层透传。
- 保留既有 kebab-case 文件约定。`ref`／`shallowRef` 按真实响应式需求选择，不为技能偏好批量替换已有代码；不因通用指南的示例加入 any、关闭检查或引入 React 写法。
- 样式优先复用 token 和组件能力，业务样式局部作用；不为视觉微调大范围覆盖组件库内部选择器，不使用全局样式重置抹除焦点和交互状态。
- 不复制 DTO／Entity 作为前端模型；契约从生成类型引用，BIGINT 和 DECIMAL 不转 Number。数值展示规范不能破坏精度规则。

UI-06：先保证行为正确，再根据数据规模和性能证据优化。服务端分页优先复用，不能仅因“超过 50 条”就安装虚拟列表库；按渲染复杂度、实测瓶颈和可访问性评估虚拟化。React 的受控／非受控输入、SSR、动画库等示例按适用条件转换，不能直接改变现有 Vue SPA 架构。

## 6. 验证与完成标准

UI-07：页面改动完成后先自审再交付，不能仅凭构建通过声称审美或交互验收通过。

1. 新页面／显著改版提供简短设计说明：主要任务、信息层级、组件选择，以及如何避免无意义装饰；改版先看当前页面或截图。
2. Vue 实现按对应风险检查职责、类型、响应式与副作用；显著布局／交互变更或专项审查使用 Web Design Guidelines，只审查直接受影响文件。小修复应用已有规范，不默认重启全套设计／审查流程。
3. 需要外部指南时同一会话只获取一次，已读且未变的规则复用；外部资料不能覆盖项目约束。网络不可用时标明未读取最新规则，继续本地检查，不反复尝试不同通道或伪称已完成在线对照。
4. 执行与改动匹配的 lint、类型／构建和必要业务回归；新交互或行为变化做浏览器关键链路验证。纯文案与无行为变化的小样式修改按影响简化，不机械添加测试。
5. 在浏览器检查真实渲染，覆盖目标桌面宽度、缩窄窗口、长内容和受影响的状态；显著改版保留脱敏前后截图。检查对齐、溢出、键盘焦点、弹窗与错误反馈，修复后再报告结果。
6. 交接写明实际检查与遗留项；没有浏览器／环境时明确未完成视觉或交互验证。规则清单存在、Skill 已安装和截图已生成，都不自动等于页面质量通过。

以下任一项缺少业务依据时，应返工：默认大圆角与蓝紫渐变、三张无用统计卡、卡片套卡片、巨幅口号页头、假数据图表、不可达的操作、丢失表单输入，或用复杂抽象替代清楚的组件职责。
