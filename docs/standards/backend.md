# 后端开发规范

版本：V1.0 · 规则前缀：BE。

## 1. 请求执行链

执行顺序为：请求标识／安全中间件→认证 Guard→功能权限 Guard→DTO 校验→应用 Service→受限查询与事务→输出映射→统一响应。Nest 的具体生命周期以固定版本为准，授权上下文不得由 DTO 校验后的用户输入伪造。

BE-01：认证后的上下文至少包含 userId、sessionId、deptId、securityVersion、requestId；权限按当前数据库状态解析。上下文不是把完整 HTTP Request 传遍所有层；Worker 通过任务发起人重新构建有效上下文。

| 层次 | 负责 | 不负责 |
|---|---|---|
| Controller | 路由、DTO、响应声明、公开／受保护元信息 | 直接访问多张表、编排事务、吞业务异常 |
| Guard | 身份、功能授权、端点默认保护 | 代替全部行级数据范围 |
| Service | 用例、不变量、目标归属、事务与审计 | HTTP 状态拼装、原样返回 ORM Entity |
| Query／Policy | 操作级范围、固定业务隔离、投影与索引查询 | 信任前端 SQL 字段、返回跨范围记录 |
| Entity／Migration | 存储映射与结构变化 | 页面状态、HTTP 协议、外部通知 |
| 全局 Filter／Interceptor | 安全错误与统一 JSON／requestId | 将所有异常包装为 HTTP 200 |

## 2. 公开接口与默认保护

BE-02：所有 API 默认受保护，登录和公开健康接口必须显式声明。CI／测试检查新路由的授权声明，不能因开发者忘写 Guard 而默认公开。

每个操作声明稳定 permissionCode，模块导出权限清单，由受控注册过程同步数据库。角色授权与菜单分开。列表、详情、修改、删除、统计、选项、导出、附件均进入对应操作范围，不用 list 权限代替 update 权限。

非 HTTP 入口同样调用已授权的应用用例，不因为没有 Controller 就绕过检查。必要系统任务使用显式系统主体及允许的操作集合，不能伪造超级管理员绕过所有限制。

## 3. 作用域设计

BE-03：模块先声明资源归属，再实现查询。范围由后端策略返回可信结构，不接收客户端 scope SQL。全部、本部门、下级、指定部门、本人由与当前操作关联的角色范围并集得到，再与业务固有限制取交集。

示例资源 demo.record 的本人字段为 created_by，部门字段为 owner_dept_id。两者适用于样例，不得复制到所有业务作为默认事实。无部门不获得部门范围；缺失归属策略默认拒绝，不能回退全量。

列表与 total 复用同一个范围构造，详情和写入也使用相同语义。Service 中的 `assertCanUpdate` 不能只有一个预查询，最终 SQL 仍需范围条件。基于单个可见对象创建另一个对象时，目标归属与关联引用都重新验证。

## 4. 公共能力的最小契约

以下是需建设的公共能力职责，不表示当前存在同名类或可直接 import 的 API。实现时先核查仓库，用正式接口代替本文名称，并在模块设计中引用。

| 能力 | 输入 | 输出／保证 |
|---|---|---|
| 认证上下文解析 | 当前会话或任务发起人 | 有效主体；无效立即拒绝 |
| 操作授权 | 主体、permissionCode | 允许／拒绝；不依赖菜单 |
| 数据范围解析 | 主体、resource、action、事务上下文（若有） | 可信条件描述或查询构造器，默认拒绝 |
| 成功审计 | 事务 EntityManager、动作、对象与白名单差异 | 与业务同事务持久化 |
| 幂等协调 | 用户、端点、键、摘要、事务 | 认领／原结果／冲突；并发唯一 |
| 业务文件引用 | 事务、fileId、对象类型与 ID | 文件可关联且归属合法；更新引用原子 |
| 授权代次更新 | 事务、授权影响原因 | authz_epoch 原子递增 |
| 任务受理 | 用户、类型、版本、受控过滤条件 | task＋dispatch＋幂等结果一致写入 |

新业务不可直接写 sys_user、sys_task 或 sys_file_link 绕过它们的生命周期。缺少能力时先实现最小可复用入口，不在每个业务中复制一份。

## 5. 标准新增用例

1. 校验 create 权限、DTO、编码规范化规则与目标归属。
2. 在事务内认领幂等键；同键同摘要读取原结果，同键不同摘要拒绝。
3. 校验关联对象、引用文件和业务约束。
4. 从服务端填充 createdBy、updatedBy、version=1 和 UTC 时间；写入唯一业务编码。
5. 写业务文件关联、成功审计及幂等结果。
6. 提交后返回白名单 DTO，不能先向客户端返回成功。

唯一性预检查只改善体验，数据库唯一索引负责最终并发约束。捕获重复键后映射业务错误，不能把所有数据库异常都翻译为“名称重复”。

## 6. 标准更新、删除与归属转移

BE-04：输入 expectedVersion、可变字段与对象 ID；事务内使用操作范围＋version 条件写入，检查影响条数，写审计和新版本结果。软删除同样递增 version，不因 UPDATE 的便利省略引用校验。

归属转移要求当前对象可管理、目标部门可分配、所有引用仍合法；同事务递增 authz_epoch，避免已有导出继续按旧归属下载。冻结字段和创建人不可通过 部分更新 修改。

多对象写入使用稳定锁顺序；涉及安全状态的事务先获取安全状态行，再按表与 ID 的固定顺序获取业务锁。导出完成与授权修改采用一致锁顺序，避免分别先锁 task／security 造成死锁。遇到可恢复死锁只对已证明可重试的完整事务有限重试，不能重试含未知外部副作用的片段。

## 7. 异常、日志与外部调用

BE-05：可预期业务错误映射稳定 businessCode；未知错误记录 requestId 和安全诊断，输出通用 500。catch 只有在转换、补偿或增加上下文时使用，之后保持失败语义。

数据库事务内不发短信、HTTP 请求、设备指令或写最终文件作为不可撤销动作。需要外部副作用的业务采用提交后投递及独立幂等协议；任务导出规则不能直接套用支付或设备控制。

结构化日志不记录密码、Token、完整请求体、Excel 敏感行和文件内容。成功业务审计失败时回滚对应业务；失败尝试作为独立运行／安全事件，不伪造“失败审计与已回滚事务一起成功”。

## 8. 运行与性能

限制请求体、分页、批量 ID、连接池、并发和超时。参数验证与 SQL 参数绑定并用；过滤字段与操作符都白名单。

避免 N+1、SELECT *、全表加载后 JS 过滤、无限 Promise.all。导入解析和大文件处理放隔离进程／线程或合适 Worker；仅搬进另一个 async 函数不等于避免事件循环阻塞。

依赖不健康返回明确 503；Valkey 故障不应使基础登录失效，任务降级状态明确。Server／Worker 优雅关闭，停止受理后处理在途事务和租约。代码不依赖启动顺序碰巧成立。
